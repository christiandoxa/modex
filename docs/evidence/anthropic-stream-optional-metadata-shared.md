# Anthropic stream metadata and delta handling across Prodex releases

The frozen Prodex 0.165.1 source at `10ae15b5d1806302b60f051e4e6fec788044f4c2` and 0.439.2 source at `72b77478a5198fc5da6b4d2253137f9cdbf43be9` have byte-identical Anthropic stream readers (`crates/prodex-app/src/runtime_launch/proxy_startup/anthropic_messages_sse_reader.rs`, SHA-256 `5b74e79588e7e5793abd9edf6c48bdb968745b7563b9423276ac9676ce3de6a3`) and action policies (`crates/prodex-mojo-core/src/anthropic_stream_policy.rs`, SHA-256 `bc08e05490f8b37ed8496c16d5f610aba5be2cfd49bb1e4c87ef57777044abb3`). Their compiled policy implementation at `mojo/prodex_core/anthropic_stream_policy.mojo` is also identical (SHA-256 `cb215804970ce80d90977b73623412a23ca934c45dedbfc29536684566a5bd18`).

The shared reader also tolerates missing or wrongly typed optional `message_start` metadata and usage, ignores unusable `message_delta.usage` counters, and ignores non-string text-delta payloads. `observe_value` passes optional message ID/model and usage to `observe_usage`, and passes raw optional `delta.text` onward; `observe_usage` updates counters only for values convertible with `Value::as_u64()` (reader lines 122–129, 156–161, and 381–395). The release's own stream-policy fixture has a `message_start` containing only an ID and a `message_delta` without usage (443–454).

The compiled policy defaults to `Ignore`, selects actions for `text_delta`, `input_json_delta`, and `thinking_delta`, and leaves other string delta types ignored. In an ordinary content block, a missing or non-string `delta.type` selects `MissingDeltaType` (ignored result blocks and active searches have separate precedence). The source tests explicitly expect `signature_delta` and an unknown string to be ignored. The reader converts `Ignore` to no output and emits `response.failed` for `MissingDeltaType`. This explains why both releases ignore `citation_delta`, including events with extra root fields, while keeping absent or wrongly typed delta types fail-closed.

Modex now ignores an unknown string delta type before validating fields it will not consume. It still validates the delta object and string type, and preserves the existing text and input-JSON paths. Missing, null, or numeric delta types continue to fail. `thinking_delta` is a recognized release action, so it is kept out of the unknown-type ignore path; Modex does not yet implement its reasoning events.

`tests/test_anthropic_stream_optional_metadata_shared.py` compares the real `modex super` launch path with both frozen Linux oracle binaries. It covers 24 optional-metadata variants, a repeated-search input-JSON stream with extra event-root fields, six unknown string type variants (`citation_delta`, `signature_delta`, and `future_delta`, each with and without an extra root field), and six missing/null/numeric type variants with and without an extra root field. The unknown-type streams produce the same normalized response events in Modex and both releases. All malformed-type cases produce `response.failed` in all three processes, though their failure diagnostics are not identical: the releases use `invalid_anthropic_stream` and append `response.created`, while Modex uses `provider_stream_error` and emits only the failure event.

The same suite records a separate known mismatch for `thinking_delta`. The frozen reader's `native_anthropic_stream_emits_live_reasoning_events` unit test covers an in-order thinking block. Both release binaries also emit reasoning events and complete for that shape and for a delta with no preceding block. Modex fails the in-order stream at the unsupported `thinking` block and fails the out-of-order stream at the unsupported `thinking_delta` event. This comparison keeps the known action distinct from unknown strings; it does not claim reasoning parity.

Each test run isolates HOME, state, work, and loopback ports, uses a fake Codex client and `synthetic-provider-key`, and makes no external provider requests. The suite checks the oracle SHA-256 values:

- Prodex 0.165.1: `dd5a4354e067cbbb44e00a2fd1f59843aeb267d17db116e37896d5e305279a51`
- Prodex 0.439.2: `a545b602bddfbbc2b4455d8dd7e97263e9c49747fa9d1d6b94011e73971d2a5e`

Reproduce with `make build` followed by `python3 scripts/ci/run-unittest.py test_anthropic_stream_optional_metadata_shared.py`. Fast and Full CI run this check in the existing cross-release lane after acquiring both pinned oracles.

Citation data is still not translated into Responses output; the releases also ignore these citation events. This evidence does not establish parity for `thinking_delta`, other malformed Anthropic fields, other providers, or the six release targets. The broader inventory remains incomplete.
