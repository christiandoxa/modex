Terminal width gap evidence

Reproduce from the repository root:

    make build
    python3 scripts/ci/run-unittest.py test_terminal_dimensions.py

The test creates a synthetic launch environment with a 24-row, 42-column
controlling PTY, `TERM=dumb`, and a synthetic Codex executable that reports the
below-minimum version. It compares the production CLI against both frozen
Linux x86-64 release oracles. The first `[ Prodex Launch ]` fallback panel
line is 42 cells for Prodex 0.165.1 and Prodex 0.439.2, but 110 cells for
Modex. It confirms no provider request or launch overlay remains. This test
records a known mismatch; it does not count terminal parity as complete.

The existing `probes/gaps/terminal.mojo` checks the relevant Mojo 1.2.0
standard-library surface. Running:

    mojo build probes/gaps/terminal.mojo

fails at `from std.os import openpty, terminal_size` because `std.os` exports
neither symbol. In the pinned Prodex 0.165.1 and 0.439.2 sources,
`crates/prodex-terminal-ui/src/terminal.rs` opens `/dev/tty` and runs `stty
size` on Unix before using the 110-column fallback. The explicit
`PRODEX_TERM_COLUMNS` override path is already implemented in Modex and
covered against both release oracles. Under the project restriction against
external `stty` helpers and new native bindings, no production API can acquire
the controlling-terminal dimensions.

The complete `TERMINAL` parity row therefore remains `NOT_STARTED`; only
fallback and explicit-width slices are characterized. Interactive rendering,
height, resize, signal handling, cleanup, and non-Linux targets remain
unverified or unfinished.
